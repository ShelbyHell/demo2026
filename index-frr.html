Настройка корпоративной сети HQ ↔ BR

Руководство для стенда на базе ALT Linux + FRR (Free Range Routing). Роутеры HQ-RTR и BR-RTR — обычные Linux-машины: сеть через /etc/net/ifaces, GRE через ip tunnel, OSPF через FRR vtysh, NAT через iptables.

FRR / vtysh ALT Linux OSPF MD5 GRE iptables · MASQUERADE DHCP · ISC SSH

00📘 Как пользоваться этой методичкой

Это руководство по настройке сети с использованием FRR (Free Range Routing). HQ-RTR и BR-RTR — обычные Linux-серверы (ALT Linux) с пакетом frr. Вся конфигурация роутинга делается через vtysh, сетевые интерфейсы настраиваются через стандартные ALT-механизмы /etc/net/ifaces/.

🦓
Что такое FRR Free Range Routing — опенсорсный стек маршрутизации для Linux (форк Quagga). Поддерживает OSPF, BGP, IS-IS, RIP, MPLS и многое другое. Управляется через общий шелл vtysh с синтаксисом, похожим на Cisco IOS. Страница проекта: frrouting.org.

Устройства в стенде

📍
  • ISP — внешний роутер, от него идёт интернет (ALT Linux + iptables).
  • HQ-RTR — центральный офис: ALT Linux + FRR, VLAN-сабинтерфейсы, GRE, OSPF, NAT, DHCP.
  • BR-RTR — филиал: ALT Linux + FRR, LAN, GRE, OSPF, NAT.
  • HQ-SRV — сервер: DNS (BIND), RAID, NFS.
  • BR-SRV — сервер домена Samba DC.
  • HQ-CLI — рабочая станция, получает адрес по DHCP.

03⚙️ Базовая настройка устройств

ℹ️
ALT Linux: сеть через /etc/net/ifaces На всех Linux-машинах сетевые настройки хранятся в /etc/net/ifaces/<iface>/. Файл ipv4address — адрес, ipv4route — маршруты, resolv.conf — DNS, options — тип и параметры интерфейса. После изменений — systemctl restart network.

ISP

bash
[root@stendssa ~]# hostnamectl set-hostname isp
[root@isp ~]#

HQ-RTR (ALT Linux)

Hostname и IP-форвардинг

bash
[root@alt ~]# hostnamectl set-hostname hq-rtr.au-team.irpo

# Включить IP-форвардинг
[root@hq-rtr ~]# nano /etc/net/sysctl.conf
diff
- net.ipv4.ip_forward = 0
+ net.ipv4.ip_forward = 1
bash
[root@hq-rtr ~]# systemctl restart network
[root@hq-rtr ~]# sysctl net.ipv4.ip_forward    # должно быть = 1

Uplink-интерфейс (enp6s20 — сторона ISP)

bash
[root@hq-rtr ~]# echo "172.16.1.2/28" > /etc/net/ifaces/enp6s20/ipv4address
[root@br-rtr ~]# echo "nameserver 95.167.167.95" > /etc/net/ifaces/enp6s20/resolv.conf
[root@hq-rtr ~]# echo "default via 172.16.1.1" > /etc/net/ifaces/enp6s20/ipv4route

Настройка работы интерфейсов

bash
[root@hq-rtr ~]# echo "TYPE=eth" >> /etc/net/ifaces/enp6s19/options
[root@hq-rtr ~]# echo "TYPE=eth" >> /etc/net/ifaces/enp6s20/options
[root@hq-rtr ~]# echo "TYPE=eth" >> /etc/net/ifaces/enp6s21/options

VLAN-сабинтерфейсы на enp6s21 (LAN-транк)

💡

TYPE=vlan

[root@hq-rtr ~]# nano /etc/net/ifaces/enp6s21.200/options

TYPE=vlan
BOOTPROTO=static
VID=200
HOST=enp6s21

[root@hq-rtr ~]# mkdir -p /etc/net/ifaces/enp6s21.999
[root@hq-rtr ~]# nano /etc/net/ifaces/enp6s21.999/options
Прописываем содержимое ниже в файл:

04🌍 Настройка ISP: IP, NAT, форвардинг

bash
# Скопировать шаблон интерфейса
[root@isp ~]# cp -r /etc/net/ifaces/ens19 /etc/net/ifaces/ens20
[root@isp ~]# cp -r /etc/net/ifaces/ens19 /etc/net/ifaces/ens21

# Убрать маршрут по умолчанию у внутренних интерфейсов
[root@isp ~]# rm -rf /etc/net/ifaces/ens2*/ipv4route

# Назначить адреса
[root@isp ~]# echo "172.16.1.1/28" > /etc/net/ifaces/ens20/ipv4address
[root@isp ~]# echo "172.16.2.1/28" > /etc/net/ifaces/ens21/ipv4address

[root@isp ~]# systemctl restart network
[root@isp ~]# ip -c a

Форвардинг

bash
[root@isp ~]# nano /etc/net/sysctl.conf
diff
- net.ipv4.ip_forward = 0
+ net.ipv4.ip_forward = 1
bash
[root@isp ~]# systemctl restart network
[root@isp ~]# sysctl net.ipv4.ip_forward

# NAT (MASQUERADE)
[root@isp ~]# iptables -t nat -A POSTROUTING -s 172.16.1.0/28 -o ens19 -j MASQUERADE
[root@isp ~]# iptables -t nat -A POSTROUTING -s 172.16.2.0/28 -o ens19 -j MASQUERADE

[root@isp ~]# iptables-save >> /etc/sysconfig/iptables
[root@isp ~]# systemctl enable --now iptables

[root@isp ~]# iptables -t nat -L -n -v    # проверка

11🌐 NAT на роутерах (iptables)

🦓
Вместо EcoRouter NAT — стандартный Linux iptables MASQUERADE на внешнем интерфейсе. Правила сохраняются в /etc/sysconfig/iptables и восстанавливаются сервисом iptables.

HQ-RTR

bash
# MASQUERADE для всех внутренних подсетей через uplink enp6s20
[root@hq-rtr ~]# iptables -t nat -A POSTROUTING -s 192.168.100.0/27 -o enp6s20 -j MASQUERADE
[root@hq-rtr ~]# iptables -t nat -A POSTROUTING -s 192.168.200.0/24 -o enp6s20 -j MASQUERADE
[root@hq-rtr ~]# iptables -t nat -A POSTROUTING -s 192.168.99.0/29  -o enp6s20 -j MASQUERADE

# Туннельный трафик NAT-ить не нужно — он уже инкапсулирован
# Сохранить и активировать при загрузке
[root@hq-rtr ~]# iptables-save >> /etc/sysconfig/iptables
[root@hq-rtr ~]# systemctl enable --now iptables

[root@hq-rtr ~]# iptables -t nat -L -n -v    # проверка

BR-RTR

bash
[root@br-rtr ~]# iptables -t nat -A POSTROUTING -s 192.168.0.0/28 -o enp6s20 -j MASQUERADE

[root@br-rtr ~]# iptables-save >> /etc/sysconfig/iptables
[root@br-rtr ~]# systemctl enable --now iptables

[root@br-rtr ~]# iptables -t nat -L -n -v

07👤 Создание пользователей

🔑
Все устройства — Linux Теперь HQ-RTR и BR-RTR — тоже Linux-машины, поэтому везде используем стандартный useradd. Никаких EcoRouter-специфичных команд нет.

HQ-SRV / BR-SRV / HQ-RTR / BR-RTR

Выполнить на каждой машине:

bash
[root@hq-rtr ~]# useradd -u 2026 sshuser
[root@hq-rtr ~]# passwd sshuser              # ввести P@ssw0rd
[root@hq-rtr ~]# usermod -aG wheel sshuser
[root@hq-rtr ~]# echo "sshuser ALL=(ALL:ALL) NOPASSWD: ALL" >> /etc/sudoers
📋
Повторить те же команды на BR-RTR, HQ-SRV, BR-SRV — меняется только приглашение оболочки.

09🛡️ GRE-туннель (Linux ip tunnel)

🦓
Нет EcoRouter — делаем через Linux kernel + FRR GRE-туннель создаётся средствами ядра (ip tunnel), сохраняется в /etc/net/ifaces/ для автоподнятия при рестарте. IP-адрес туннеля назначается тут же; OSPF запустим поверх него в следующем разделе.
Конец туннеляАдресLocalRemote
HQ-RTR10.10.10.1/30172.16.1.2172.16.2.2
BR-RTR10.10.10.2/30172.16.2.2172.16.1.2

HQ-RTR — создание GRE в /etc/net/ifaces

bash
[root@hq-rtr ~]# mkdir -p /etc/net/ifaces/tunnel0
[root@hq-rtr ~]# nano /etc/net/ifaces/tunnel0/options
Вносим в файл следующее содержимое: 
TYPE=iptun
TUNTYPE=gre
TUNLOCAL=172.16.1.2
TUNREMOTE=172.16.2.2
TTLMODE=fixed
TTL=255
BOOTPROTO=static
Сохраняем (Ctrl-S, Ctrl-X), и пишем следующее 
[root@hq-rtr ~]# echo "10.10.10.1/30" > /etc/net/ifaces/tunnel0/ipv4address
[root@hq-rtr ~]# systemctl restart network
[root@hq-rtr ~]# ip -c a show tunnel0
[root@hq-rtr ~]# ip link show tunnel0

21🔀 Статический NAT (DNAT) через iptables

Статический NAT (DNAT) позволяет пробросить внешний порт на внутренний сервер. Здесь — проброс порта 80 с внешнего интерфейса ISP до HQ-SRV (или BR-SRV) через роутер.

💡
Вместо EcoRouter static NAT В EcoRouter использовалось ip nat source static. На Linux делаем то же самое через iptables -t nat -A PREROUTING ... -j DNAT.

Пример: проброс TCP/80 с ISP → HQ-SRV (192.168.100.2)

ПараметрЗначение
Внешний IP (HQ-RTR uplink)172.16.1.2
Внешний порт80
Внутренний IP (HQ-SRV)192.168.100.2
Внутренний порт80

HQ-RTR

bash
# DNAT: входящий трафик на 172.16.1.2:80 → HQ-SRV:80
[root@hq-rtr ~]# iptables -t nat -A PREROUTING -i enp6s20 -p tcp --dport 80 -j DNAT --to-destination 192.168.100.2:80

# Разрешить форвардинг к HQ-SRV
[root@hq-rtr ~]# iptables -A FORWARD -p tcp -d 192.168.100.2 --dport 80 -j ACCEPT

# Сохранить
[root@hq-rtr ~]# iptables-save >> /etc/sysconfig/iptables
[root@hq-rtr ~]# systemctl restart iptables

# Проверка
[root@hq-rtr ~]# iptables -t nat -L PREROUTING -n -v

Аналогично для BR-RTR → BR-SRV

bash
[root@br-rtr ~]# iptables -t nat -A PREROUTING -i enp6s20 -p tcp --dport 80 -j DNAT --to-destination 192.168.0.2:80
[root@br-rtr ~]# iptables -A FORWARD -p tcp -d 192.168.0.2 --dport 80 -j ACCEPT
[root@br-rtr ~]# iptables-save >> /etc/sysconfig/iptables
[root@br-rtr ~]# systemctl restart iptables

Проверка с ISP

bash
[root@isp ~]# curl -I http://172.16.1.2    # должен ответить HQ-SRV (nginx)
[root@isp ~]# curl -I http://172.16.2.2    # должен ответить BR-SRV
